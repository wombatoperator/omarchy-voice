Why this is a tool and not a prompt

A launch command returns before the window exists, so an assistant issuing its own move and focus calls is addressing windows that have not been mapped yet — every placement races the application it is placing. compose_windows waits for each window to appear, moves it if a window rule sent it elsewhere, then preselects the split for the next one. Whatever did not come up is named in the reply rather than reported as open.

One sentence, four dispatches

recorded run
omarchy-voice say 6.2 s · dry run
heardclose the grok terminal but leave the other one alone, then make what's left full screen
actionhl.dsp.focus({ window = "address:0x563a0c73c2d0" })
actionhl.dsp.window.close()
actionhl.dsp.focus({ window = "address:0x563a0c76eef0" })
actionhl.dsp.window.fullscreen({ mode = "fullscreen" })
replyClosed the grok terminal; the other is now fullscreen.

Both windows were foot terminals on the same workspace. The class name could not tell them apart, so the model queried the window list, matched on title, and targeted by address — then ordered the four calls so the survivor was the one that went fullscreen.

Why a model, not a grammar

the argument

Every phrase-grammar voice tool ends up with a wiki page of exact incantations, and “switch me to the workspace with the browser on it” is never on it. The grammar makes you learn its vocabulary instead of the other way round.

But handing a model a microphone is only interesting if it knows what it is holding. The part of this add-on that actually matters is not the API call — it is what the model is told before the call.

It reads the machine, not a manual

21,771 chars, rebuilt on update

On first run omarchy-voice compiles a capability manifest from four live sources. Nothing about the desktop API is hardcoded, so the assistant is correct for your Hyprland and your Omarchy — and stays correct after an update, with nothing to re-teach.

Source on this machineWhat it contributes
/usr/share/hypr/stubs/hl.meta.lua Every dispatcher, read from Hyprland's own type stub — cursor, window, workspace, group namespaces
default/hypr/bindings/*.lua Real call syntax, verified by the fact that your desktop binds it to keys right now
omarchy commands --json The whole CLI with arguments and summaries; hidden and sudo-requiring commands filtered out
hyprctl -j + .desktop files Your monitors, workspaces, open windows and installed apps — refreshed every request

This is load-bearing. Hyprland 0.56 moved to a Lua dispatch API: hyprctl dispatch workspace 1 is dead, and a model working from memory writes it anyway. Reading the stub means it writes hl.dsp.focus({ workspace = "1" }) instead. omarchy-voice manifest prints exactly what it knows.

The signal chain

teal = stays on the machine
01 · LOCAL

Toggle

SUPER + SHIFT + V. Until it is on there is no recorder process at all.

02 · LOCAL

Microphone

pw-record off PipeWire, 24 kHz mono, in 100 ms frames.

03 · OPENAI

Realtime

Audio streams to gpt-realtime while listening is on. No local transcription step.

04 · OPENAI

Decide

Persona, the capability manifest, and a desktop snapshot refreshed every turn.

05 · LOCAL

Policy gate

Every call checked before it runs. Denied, held, or allowed.

06 · LOCAL

Act

hyprctl · omarchy · wtype · uwsm-app, then a notification and bar state.

While listening is on, room audio streams continuously to OpenAI. There is no local recognition step and no wake word to hold it back — the gate is the toggle, and it is the whole gate. Off, no pw-record is running, so there is nothing being captured and discarded. That is the trade the speed is bought with, and it is the first thing to know about this program.

An open microphone is untrusted input

12 deny · 13 confirm rules

A television in the room, a person on a call, a mis-transcription — any of them can put a sentence into this pipeline. So the model's decisions are checked before they run, by rules the model cannot reach or rewrite.

VerdictCoversBehaviour
DENIED rm -rf, dd, mkfs, sudo, pkexec, ssh, passwd, curl-piped-to-shell, git push Never runs, whatever the model asks for. Deny beats confirm.
HELD shutdown, reboot, suspend, package installs, omarchy update, config resets, close-all-windows Stops and waits for you to say “confirm” out loud.
ALLOWED Window, workspace, monitor, theme, audio, brightness, screenshots, launching apps, app shortcuts Runs immediately. You asked out loud; that is the permission.
the hold, in practice 4.3 s
heardreboot the machine
heldsystemctl reboot
replySay confirm to systemctl reboot

Note the reply. The model had already narrated the reboot as done; the gate rewrote what you hear so it matches what actually happened. An assistant that says “shutting down now” and then doesn't is worse than one that refuses.

The shell tool is off by default — the model gets no arbitrary command execution unless you turn it on and accept what that means. Everything heard, decided and run is logged. The systemd unit runs under ProtectSystem=strict with a read-only home and three writable paths.

Try it without a microphone

the honest demo path

say exercises the entire pipeline except the microphone, so you can watch what a sentence turns into before you trust it with an open mic. Add --dry-run and it decides but narrates instead of acting. 

# the whole pipeline, minus the mic
$ omarchy-voice say "what windows do I have open"
reply   Two foot terminals on workspace 1: the
        voice navigation addon and a grok session.

$ omarchy-voice say "switch to workspace four"
action  hl.dsp.focus({ workspace = "4" })
reply   Switched to workspace 4.
# check every moving part
$ omarchy-voice doctor

# what the model knows about this machine
$ omarchy-voice manifest

# decide, but touch nothing
$ omarchy-voice --dry-run say "..."

# everything it heard and did
$ omarchy-voice log -f

KNOWN LIMITThe API’s tokens-per-minute budget. About 8,200 tokens a turn against a 40,000 TPM tier is roughly five turns a minute; past that the daemon waits the interval the server names and retries rather than going silent

Measured on the realtime path: a tool call lands about 1.3 s after you stop speaking, and a three-pane workspace is built and placed in about 2 s. The manifest and persona sit in the cached prefix; the desktop snapshot is appended per turn and the stale one deleted, so the cache survives a desktop that keeps changing.

Install

idempotent, asks first 
$ git clone …/omarchy-voice
$ cd omarchy-voice
$ ./install.sh
$ omarchy-voice doctor

The installer offers the keybinding, the bar widget, the user service, and the omarchy voice … routes, asking before each. It runs without an API key — the bar just says it needs configuring.

Next, and deliberately absent

  • Clicking. Hyprland moves the cursor but has no click dispatcher, so pointer clicks need ydotool. Everything here works without it, by driving apps through their own shortcuts — faster anyway. A grid overlay is the obvious next piece.
  • Speaker identification. It answers to any voice in the room.
  • A second provider. Speech-to-speech realtime is OpenAI and Gemini Live and not much else, both paid and proprietary, so an abstraction layer buys almost no coverage. realtime.py is the seam if that changes.
